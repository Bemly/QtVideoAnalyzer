# H.263 码率 / Annex 速查（一页）

> 数据模块：`qt_analyzer/rc_h263.py`（标准库 only，永不抛错）。
> 本机实测：`ffmpeg 9.0.2`（`/opt/homebrew/bin/ffmpeg`）。

## 1. 本机 encoder 能力（`ffmpeg -hide_banner -h encoder=h263[h263p]` 关键行）

```text
Encoder h263 [H.263 / H.263-1996]:
    General capabilities: dr1 reorderedopaque
    Threading capabilities: none
    Supported pixel formats: yuv420p
Encoder h263p [H.263+ / H.263-1998 / H.263 version 2]:
    General capabilities: dr1 threads reorderedopaque
    Threading capabilities: slice
    Supported pixel formats: yuv420p
H.263p encoder AVOptions:
  -umv               <boolean>    E..V....... Use unlimited motion vectors. (default false)
  -aiv               <boolean>    E..V....... Use alternative inter VLC. (default false)
  -obmc              <boolean>    E..V....... use overlapped block motion compensation. (default false)
  -structured_slices <boolean>    E..V....... Write slice start position at every GOB header ... (default false)
```

结论：**无 `-profile` 开关**（profile = 选编码器：`h263` 即 Baseline，
`h263p` 即 H.263+）；**chroma 只有 `yuv420p`**（`rc.chroma_modes() == ["420"]`）；
`h263p` 额外暴露 `-umv/-aiv/-obmc/-structured_slices`，无 B 帧相关开关。

## 2. Profile / Annex 对照（`rc.profiles()`）

| Profile | 标准版本 | ffmpeg 编码器 | Annex（本任务口径 D/F/I/J/T 加粗） |
|---|---|---|---|
| Baseline | H.263-1996 | `h263` | 无 Annex：I/P + 半像素 MV + GOB + VLC；**尺寸硬限制** 128x96 / 176x144 / 352x288 / 704x576 / 1408x1152（本机实测 640x360 直接报错 `not valid for the H.263 codec`） |
| **H.263+** | H.263-1998 (v2) | `h263p` | **D** UMV（`-umv`）/ **F** 高级预测 OBMC+4MV（`-obmc`）/ **I** 高级帧内 AIC / **J** 去块滤波 / **T** 修正量化（I/J/T 本机构建无开关）+ E/G/K(`-structured_slices`)/L/M/N/O/P/Q/R/S(`-aiv`) |
| **H.263++** | H.263-2000 | `h263p`（超集兼容） | H.263+ 全集 + U（增强参考帧选择）/ V（数据分区条带）/ W（额外 SEI）/ X（profile/level 定义） |

Level 口径（Annex X 图像格式，= 上表 Baseline 固定尺寸）：
SQCIF 128x96 → QCIF 176x144 → CIF 352x288 → 4CIF 704x576 → 16CIF 1408x1152。

## 3. 码率速查（`rc.recommend(w,h,fps)`，CBR 为主，会议口径 64kbps~1Mbps）

算法：`bpp=0.12 × wh×fps`，钳到 [64k, 1000k] 后就高 snap 到梯子
`24/32/48/64/96/128/192/256/384/512/768/1000k`；`use="3g"` 走
3G-324M 口径（bpp=0.10，上限 64k，共路含 AMR 音频）。

| 场景 | `recommend()` | 典型 ffmpeg（CBR） |
|---|---|---|
| SQCIF 128x96@10（3G 可视电话下限） | 64k（videoconf 下限钳）/ 3G 口径 24k | `-c:v h263 -b:v 24k -minrate 24k -maxrate 24k -bufsize 48k -g 40 -bf 0` |
| QCIF 176x144@10~15（会议/3G 主力） | 64k / 3G 口径 32~48k | `-c:v h263p -b:v 64k -minrate 64k -maxrate 64k -bufsize 128k -g 60 -bf 0` |
| CIF 352x288@15（会议主力） | **192k** | `-c:v h263p -b:v 192k -minrate 192k -maxrate 192k -bufsize 384k -g 60 -bf 0` |
| CIF 352x288@30 | 384k | 同上结构，`-b:v 384k -bufsize 768k -g 120` |
| 4CIF 704x576@15 | 768k | `-b:v 768k -bufsize 1536k -g 60` |
| 4CIF 704x576@30 | 1000k（上限钳） | `-b:v 1000k -bufsize 2000k -g 120` |

VBR 备选（画质稳、峰值不可控，会议慎用，本机已验证可编）：
去掉 `-minrate`，改 `-qscale:v 2..5`。

## 4. 无 B 帧对码率的影响

* 全片只有 I/P（本机实测 CIF@15 编码 45 帧 = **1×I + 44×P，0×B**，
  目标 192k / 实际 ~239k：短片 + 高运动 testsrc2 下 I 尖峰顶穿 buf，
  长会议头肩像会贴近目标）。
* P 帧偏大、I 尖峰更陡 → CBR 缓冲（`-bufsize 2x`）必须留足，否则抖；
  同画质平均码率约 AVC 的 **2x**（`codec_avc_h263.describe()` 同口径）。
* 好处：无重排延迟，pts==dts（见 §5）。

## 5. 本工具联动（看图指南，对应 `codec_avc_h263.py`）

* **纯前向 arcs**：`reference_arcs()` H.263 只发 P 的前向边（`fwd`），
  B 的 `fwd+bwd` 双边永不出现 → motion/参考图只有绿线往前指。
* **REORDER 零线**：无 B ⇒ 无 pts−dts 重排，第 6 泳道为 **0 直线**。
* **QP 宽台阶**：量化步长翻倍档，`qp_signature_note("h263")` 即
  “范围粗、台阶跳变”，P 帧随运动抖动大（AVC 则是带宽窄=率失真优）。
* **GOB 行条 overlay**：`partition_overlay(w,h,"h263")` 每 3 行 MB
  （48px）一条 `gob` 橙线 + 8x8 `blk` 灰网格；`paint_hint()` 一句话：
  “纯前向 arcs（无 B 帧）+ REORDER 零线（pts==dts）+ QP 宽台阶 + GOB 行条 overlay”。
